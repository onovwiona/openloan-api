Loan Applications Review & Processing

Admin • Staff

Review customer loan applications, verify eligibility, and make approval/rejection decisions

View Loan Applications

GET
/api/v1/loan-applications
List all loan applications. Filter by status (draft, submitted, approved, rejected)
GET
/api/v1/loan-applications/{id}
Get specific loan application with full details
GET
/api/v1/users/{user}/loan-applications
View all applications for specific customer

Verify & Process Applications

POST
/api/v1/loan-applications/{id}/verify
Approve and move application to 'approved' status
POST
/api/v1/loan-applications/{id}/reject
Reject application with reason. Status: 'rejected'
POST
/api/v1/users/{user}/loan-applications/{id}/verify
Verify a customer's loan application by ID
POST
/api/v1/users/{user}/loan-applications/{id}/reject
Reject a customer's loan application by ID
PATCH
/api/v1/loan-applications/{id}/payroll
Update payroll information or deductions for a loan application
POST
/api/v1/users/{user}/loan-applications/{application}/approve
Approve a user's specific loan application
POST
/api/v1/users/{user}/loan-applications/{application}/reject
Reject a user's specific loan application with reason
POST
/api/v1/users/{user}/loan-applications/{application}/disburse
Disburse an approved application for a specific user
⚠️ Verification checks: Customer KYC must be 'verified', all required application documents uploaded and verified, amount within product constraints, tenure within product range, loan product requirements met. Note: `repayment_plan` is required for non-government products (government defaults to `monthly`). Employment/payroll fields are sourced from the customer's employment profile where available.

Loans Management & Disbursement

Admin • Staff

Manage disbursed loans, track repayments, and handle loan lifecycle

View Loans

GET
/api/v1/loans
List all disbursed loans. Filter by status, customer, product
GET
/api/v1/loans/{id}
Get loan details with repayment schedule and balance
POST
/api/v1/loans/{id}/approve
Approve loan application and create loan record
POST
/api/v1/loans/{id}/disburse
Disburse approved loan, funding the customer's wallet first; LOAN_REPAY account balance increases with loan principal to track outstanding balance
POST
/api/v1/loans/{id}/repay
Record loan repayment from customer
POST
/api/v1/loans/{id}/reject
Reject loan application with reason
POST
/api/v1/loans/{id}/restructure
Modify loan terms (tenure, rate, etc.)
POST
/api/v1/loans/{id}/writeoff
Write off loan (bad debt)
ℹ️ Upon disbursement: Ledger entries created, repayment schedule generated, funds credited to wallet first, LOAN_REPAY account credited with loan principal, referrer receives commission notification
6.5

Wallet Deposits & Direct Loan Repayments

Admin • Staff

Manage customer wallet deposits and process direct loan repayments (bypassing wallet validation)

Wallet Deposits

POST
/api/v1/admin/wallets/{walletId}/deposits
Deposit funds directly into customer wallet account

Direct Loan Repayments

POST
/api/v1/admin/loans/{loanId}/repayments
Process direct loan repayment (cash, bank transfer, card, etc.)
⚠️ Direct repayments bypass wallet balance validation. Use for cash payments, bank transfers, or card transactions.
ℹ️ Wallet deposits credit customer wallet accounts. Direct repayments post directly to loan accounts without wallet deduction.
Sample Wallet Deposit Payload: 
{
  "amount": 100000.00,
  "payment_method": "cash",
  "reference": "Cash deposit at branch",
  "notes": "Customer brought cash for deposit"
}
Sample Direct Repayment Payload: 
{
  "amount": 50000.00,
  "payment_method": "bank_transfer",
  "external_reference": "BT20241201001",
  "skip_wallet": true,
  "notes": "Bank transfer from customer's account"
}

Authentication & Authorization

All endpoints require JWT token in Authorization header. Role-based access control:

Role Permissions
Admin Full access - create/update/delete account types, loan products, manage all users and loans
Staff View users/accounts/loans, verify/reject KYC and applications, process disbursements
Secretary Read-only access to customer profiles and KYC documents
Marketer View referral data and customer information

Authorization: Bearer {jwt_token}
