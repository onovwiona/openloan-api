⚙️ Admin & Staff Management

Complete endpoint reference for admin and staff operations and loan processing

1

User Management

Admin • Staff

View, filter, and manage customer and staff user accounts

GET
/api/v1/users
List all users (paginated). Filter by role, status, etc.
GET
/api/v1/users/{id}
Get specific user details with roles and profiles
2

Account Management

Admin • Staff

View and manage customer accounts (Wallet, Savings, Loan Repayment, etc.)

GET
/api/v1/accounts
List all customer accounts. Filter by status, type, customer
GET
/api/v1/accounts/{id}
Get account details with balance and transactions
GET
/api/v1/users/{user}/accounts
List all accounts for specific customer
GET
/api/v1/users/{user}/accounts/{account}
Get specific user account details
3

Account Types Management

Admin Only

View and manage account type definitions (Wallet, Savings, Loan Repay, etc.)

GET
/api/v1/account-types
List all account types available to customers
POST
/api/v1/account-types
Create new account type with constraints
GET
/api/v1/account-types/{id}
Get account type details
ℹ️ Examples: WAL (Wallet), SAV (Savings), LOAN_REPAY (Loan Repayment with overdraft capability)
4

Loan Products Management

Admin Only

Create and manage loan product offerings with requirements and constraints

GET
/api/v1/loan-products
List all loan products
POST
/api/v1/loan-products
Create new loan product with terms and requirements
GET
/api/v1/loan-products/{id}
Get loan product details including requirements
Field Type Purpose
min_amount Numeric Minimum loan amount allowed
max_amount Numeric Maximum loan amount allowed
tenure_min_months Integer Minimum repayment period in months
tenure_max_months Integer Maximum repayment period in months
interest_rate Numeric Interest rate percentage
requires_guarantor Boolean Whether loan requires guarantors
5

Loan Applications Review & Processing

Admin • Staff

Review customer loan applications, verify eligibility, and make approval/rejection decisions

View Loan Applications

GET
/api/v1/loan-applications
List all loan applications. Filter by status (draft, submitted, approved, rejected)
GET
/api/v1/loan-applications/{id}
Get specific loan application with full details
GET
/api/v1/users/{user}/loan-applications
View all applications for specific customer

Verify & Process Applications

POST
/api/v1/loan-applications/{id}/verify
Approve and move application to 'approved' status
POST
/api/v1/loan-applications/{id}/reject
Reject application with reason. Status: 'rejected'
POST
/api/v1/users/{user}/loan-applications/{id}/verify
Approve specific user's application
POST
/api/v1/users/{user}/loan-applications/{id}/reject
Reject specific user's application with reason
⚠️ Verification checks: Customer KYC must be 'verified', all required application documents uploaded and verified, amount within product constraints, tenure within product range, loan product requirements met
6

Loans Management & Disbursement

Admin • Staff

Manage disbursed loans, track repayments, and handle loan lifecycle

View Loans

GET
/api/v1/loans
List all disbursed loans. Filter by status, customer, product
GET
/api/v1/loans/{id}
Get loan details with repayment schedule and balance
GET
/api/v1/users/{user}/loans
View all loans for specific customer
GET
/api/v1/users/{user}/loans/{id}
Get specific user loan details

Loan Operations

POST
/api/v1/loans/{id}/approve
Approve loan application and create loan record
POST
/api/v1/loans/{id}/disburse
Disburse approved loan to customer's LOAN_REPAY account
POST
/api/v1/loans/{id}/repay
Record loan repayment from customer
POST
/api/v1/loans/{id}/reject
Reject loan application with reason
POST
/api/v1/loans/{id}/restructure
Modify loan terms (tenure, rate, etc.)
POST
/api/v1/loans/{id}/writeoff
Write off loan (bad debt)
ℹ️ Upon disbursement: Ledger entries created, repayment schedule generated, LOAN_REPAY account credited, referrer receives commission notification
7

KYC & Document Verification

Admin • Staff

Review customer KYC documents and verify identity for loan eligibility. Handle both core KYC and application-specific documents.

Core KYC Documents (Customer Identity)

GET
/api/v1/kyc
List all customer KYC profiles. Filter by status (pending, verified, rejected)
GET
/api/v1/kyc/{profile}
View customer core KYC documents and status
GET
/api/v1/customers/{user}/kyc
View specific customer core KYC details

Per-Document KYC Verification

PATCH
/api/v1/kyc/{profile}/documents/{document_type}/verify
Verify specific KYC document (passport_photo, id_card_front, id_card_back)
PATCH
/api/v1/kyc/{profile}/documents/{document_type}/reject
Reject specific KYC document with reason

Application-Scoped Documents

GET
/api/v1/loan-applications/{application}/documents
View all documents uploaded for specific loan application
PATCH
/api/v1/loan-applications/{application}/documents/{document}/verify
Verify application document (collateral, guarantor notes, etc.)
PATCH
/api/v1/loan-applications/{application}/documents/{document}/reject
Reject application document with reason

KYC Profile Management

PATCH
/api/v1/kyc/{profile}/verify
Approve entire customer KYC profile. Status: 'verified'
PATCH
/api/v1/kyc/{profile}/reject
Reject entire KYC profile with reason. Status: 'rejected'
PATCH
/api/v1/kyc/{profile}
Update KYC profile (admin only)
DELETE
/api/v1/kyc/{profile}
Delete KYC profile (admin only)
ℹ️ Core KYC documents (passport, ID cards) are shared across all applications. Application documents (collateral, guarantor notes) are specific to each loan application.
⚠️ Document verification is required before loan approval. Use per-document endpoints for granular control over verification status.

Authentication & Authorization

All endpoints require JWT token in Authorization header. Role-based access control:

Role Permissions
Admin Full access - create/update/delete account types, loan products, manage all users and loans
Staff View users/accounts/loans, verify/reject KYC and applications, process disbursements
Secretary Read-only access to customer profiles and KYC documents
Marketer View referral data and customer information

Authorization: Bearer {jwt_token}
