🛍️ Customer Lifecycle

Complete journey from registration to loan approval, document uploads, and repayment

1

Registration & Referral

Customer registers via referral code (marketer, staff, secretary, or another customer)

POST
/api/v1/register
Register new customer with optional referral code
POST
/api/v1/login
Login and receive JWT token
ℹ️ Referrer receives notification and commission eligibility when customer makes first loan disbursement
2

Browse Account Types & Loan Products

Customer views available account types and loan products to understand options

GET
/api/v1/account-types
List all available account types (Wallet, Savings, etc.)
GET
/api/v1/account-types/{id}
Get specific account type details
GET
/api/v1/loan-products
List all available loan products with terms and requirements
GET
/api/v1/loan-products/{id}
Get specific loan product details and requirements
3

Create Accounts

Customer creates Wallet and Loan Repayment accounts for transactions

POST
/api/v1/user/accounts
Create new account (Wallet, Savings, etc.)
GET
/api/v1/user/accounts
View all customer accounts
GET
/api/v1/user/accounts/{account}/statements
View account statement and transactions
⚠️ LOAN_REPAY account type is required for loan applications. System auto-creates one per application if needed.
4

Upload Core KYC Documents

Customer uploads identity documents (passport photos, ID cards) that persist across all loan applications

POST
/api/v1/user/kyc
Upload core KYC documents (passport_photo, id_card_front, id_card_back)
POST
/api/v1/user/kyc/single/{document_type}
Upload single KYC document (passport_photo, id_card_front, id_card_back)
GET
/api/v1/user/kyc
View KYC status and uploaded core documents
ℹ️ Core KYC documents are shared across all loan applications. Upload once, use everywhere.
⚠️ Duplicate uploads are prevented while documents are pending verification. KYC must be 'verified' before loan submission.
Sample KYC Upload Payload: 
{
  "documents": {
    "passport_photo": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAAAQ...",
    "id_card_front": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAAAQ..."
  }
}
5

Apply for Loan

Customer creates draft loan application specifying amount, tenure, and loan product

POST
/api/v1/user/loan-applications
Create loan application (status: draft). Requires LOAN_REPAY account_id
GET
/api/v1/user/loan-applications
View all loan applications with status
GET
/api/v1/user/loan-applications/{id}
Get specific loan application details
Field Type Description
account_id UUID LOAN_REPAY account for loan repayment tracking
loan_product_id UUID Selected loan product with terms and constraints
requested_amount Numeric Loan amount (must be within product min/max)
requested_tenure Integer Repayment tenure in months (must be within product range)
5.5

Upload Loan Application Documents

Customer uploads application-specific documents (collateral, guarantor notes) required by the selected loan product

POST
/api/v1/user/loan-applications/{application_id}/documents
Upload general application documents (business_plan, income_proof, etc.)
POST
/api/v1/user/loan-applications/{application_id}/collateral
Upload collateral documents (PDF only) for secured loans
POST
/api/v1/user/loan-applications/{application_id}/guarantors/{guarantor_id}/notes
Upload guarantor notes (PDF or photos) for loans requiring guarantors
GET
/api/v1/user/loan-applications/{application_id}/documents
View all documents uploaded for this loan application
ℹ️ These documents are specific to this loan application and cannot be reused for other applications.
⚠️ Document requirements depend on the loan product selected. Check product details for mandatory uploads.
Sample Collateral Upload Payload: 
{
  "document": "data:application/pdf;base64,JVBERi0xLjQKJ...",
  "document_type": "title_deed",
  "description": "Property title deed for collateral"
}
Sample Guarantor Notes Upload Payload: 
{
  "note_1": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAAAQ...",
  "note_2": "data:application/pdf;base64,JVBERi0xLjQKJ..."
}
7

Submit Application for Review

Customer submits draft application for admin/staff verification (requires verified KYC)

POST
/api/v1/loan-applications/{id}/submit
Submit application for admin review (KYC must be 'verified')
⚠️ KYC must be verified AND all required application documents uploaded before submission. System validates loan product requirements.
8

Wait for Loan Review & Approval

Admin/staff review application, verify documents, and approve or reject

ℹ️ Staff will verify loan eligibility based on loan product requirements, customer KYC status, amount constraints, and income/employment details

Customer can check application status via GET /api/v1/user/loan-applications/{id}
9

Loan Disbursement

Admin/staff disburse approved loan to customer's LOAN_REPAY account. Referrer receives commission notification.

GET
/api/v1/user/loans
View disbursed loans
GET
/api/v1/user/loans/{id}
Get loan details with repayment schedule
GET
/api/v1/user/loans/{id}/schedule
View loan repayment schedule
ℹ️ Ledger entries generated. LOAN_REPAY account tracks all credit/debit transactions. Referrer receives commission via push notification.
10

Account & Profile Management

Customer manages profile information and views account statements

GET
/api/v1/user/customer-profile
View own customer profile
PATCH
/api/v1/user/customer-profile
Update profile (address, DOB, employment, income)
GET
/api/v1/me
Get authenticated user details

Authentication

All endpoints except register and login require JWT token in Authorization header:

Authorization: Bearer {jwt_token}
