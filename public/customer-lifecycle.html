🛍️ Customer Lifecycle

Complete journey from registration to loan approval, document uploads, and repayment

1

Registration & Referral

Customer registers via referral code (marketer, staff, secretary, or another customer)

POST
/api/v1/register
Register new customer with optional referral code
POST
/api/v1/login
Login and receive JWT token
ℹ️ Referrer receives notification and commission eligibility when customer makes first loan disbursement

GET

4

Upload Core KYC Documents

Customer uploads persistent identity documents (passport, ID card, driver license) that can be reused across loan applications

POST
/api/v1/user/kyc
Upload persistent core KYC documents (passport_document, id_card_front, id_card_back, driver_license, utility_bill)
POST
/api/v1/user/kyc/documents
Upload individual core KYC documents into the customer KYC profile
GET
/api/v1/user/kyc/employment-profiles
Get the customer's employment profile and uploaded employment documents
POST
/api/v1/user/kyc/employment-profiles
Create employment profile for KYC with payslip, employer ID number, and employment letter (employment/payroll fields are used server-side to populate loan applications)
PATCH
/api/v1/user/kyc/employment-profiles
Update employment profile details and income information
POST
/api/v1/user/kyc/employment-profiles/documents
Upload employment-related KYC documents (payslip_document, employer_id_card, employment_letter)
PATCH
/api/v1/user/kyc/employment-profiles/documents
Update employment document uploads for the customer's employment profile
GET
/api/v1/user/kyc/documents
List all core KYC documents uploaded for the customer
DELETE
/api/v1/user/kyc/documents/{document}
Remove an uploaded KYC document before verification
POST
/api/v1/user/kyc/passport-document
Upload persistent passport document for KYC profile
POST
/api/v1/user/kyc/id-card
Upload persistent ID card document for KYC profile
POST
/api/v1/user/kyc/passport-photo
Upload passport photo as part of the customer's persistent KYC profile
POST
/api/v1/user/kyc/guarantor-form
Deprecated. Use loan application document upload endpoint instead.
GET
/api/v1/user/kyc
View persistent KYC profile and uploaded documents
ℹ️ Core KYC documents are shared across all loan applications. Upload once, use everywhere.
ℹ️ Employment KYC adds a second profile for employer proof and payslips. Supported documents include payslip_document, employment_letter, and employer_id_card.
⚠️ Duplicate uploads are prevented while documents are pending verification. Rejected KYC documents may be replaced by uploading the same document type again.
ℹ️ Passport photo may be uploaded through the customer KYC profile via POST /api/v1/user/kyc/passport-photo. Application-specific documents still use POST /api/v1/user/loan-applications/{application}/documents.
Sample KYC Bulk Upload Form-Data (POST /api/v1/user/kyc): 
documents[0][type] = passport_document
documents[0][file] = @/path/to/passport.pdf

documents[1][type] = id_card_front
documents[1][file] = @/path/to/id_card_front.jpg

documents[2][type] = id_card_back
documents[2][file] = @/path/to/id_card_back.jpg
Sample Single Document Upload Form-Data (POST /api/v1/user/kyc/documents):

document = @/path/to/utility-bill.pdf
Sample Single File Upload Form-Data: 
POST /api/v1/user/kyc/passport-document
file = @/path/to/passport.pdf

POST /api/v1/user/kyc/id-card
file = @/path/to/id-card.jpg

POST /api/v1/user/kyc/passport-photo

5

Apply for Loan

Customer creates draft loan application specifying amount, tenure, and loan product

POST
/api/v1/user/loan-applications
Create loan application (status: draft). Requires LOAN_REPAY account_id
GET
/api/v1/user/loan-applications
View all loan applications with status
GET
/api/v1/user/loan-applications/{id}
Get specific loan application details
Field Type Description
account_id UUID LOAN_REPAY account for loan repayment tracking
loan_product_id UUID Selected loan product with terms and constraints
requested_amount Numeric Loan amount (must be within product min/max)
requested_tenure Integer Repayment tenure in months (must be within product range)
repayment_plan Enum Repayment frequency: monthly, weekly, quarterly, annually. Required for most products; optional for government loans (defaults to monthly).
employer_id_number String Employer ID number is taken from the customer's employment profile when available. Client-provided values will be ignored in favor of verified profile data.
5.5

Upload Loan Application Documents

Customer uploads application-specific documents (collateral, guarantor notes) required by the selected loan product

POST
/api/v1/user/loan-applications/{application}/documents
Upload application-specific documents (guarantor_form, bank_statement, proof_income)
POST
/api/v1/user/loan-applications/{application}/collateral
Upload collateral documents (single file upload) for secured loans
POST
/api/v1/user/loan-applications/{application}/collaterals
Upload additional collateral documents (alias endpoint for multiple collateral uploads)
POST
/api/v1/user/loan-applications/{application}/guarantors
Add a guarantor to the loan application
POST
/api/v1/user/loan-applications/{application}/guarantors/{guarantor}/notes
Upload guarantor notes (PDF or photos) for loans requiring guarantors
GET
/api/v1/user/loan-applications/{application}/documents
View all documents uploaded for this loan application
GET
/api/v1/user/loan-applications/{application}/collaterals
View collateral documents uploaded for this loan application
GET
/api/v1/user/loan-applications/{application}/guarantors
View guarantors added to this loan application
ℹ️ These documents are specific to this loan application and cannot be reused for other applications.
⚠️ Document requirements depend on the loan product selected. Check product details for mandatory uploads.
Sample Loan Application Document Upload Payload (POST /api/v1/user/loan-applications/{application}/documents): 
{
  "document_type": "proof_income",
  "file": "@/path/to/income-proof.pdf"
}

  "estimated_value": 1200000,
  "file": "@/path/to/land-title.pdf"
}

  "phone": "+2348012345678",
  "address": "123 Main St, Lagos",
  "relationship": "friend",

  "employer_phone": "+2348098765432",

{

  "file": "@/path/to/guarantor-note.pdf"
}
7

Submit Application for Review

Customer submits draft application for admin/staff verification (requires verified KYC)

POST
/api/v1/user/loan-applications/{id}/submit
Submit application for admin review (KYC must be 'verified')
⚠️ KYC must be verified AND all required application documents uploaded before submission. System validates loan product requirements.
8

Wait for Loan Review & Approval

Admin/staff review application, verify documents, and approve or reject

ℹ️ Staff will verify loan eligibility based on loan product requirements, customer KYC status, amount constraints, and income/employment details

Customer can check application status via GET /api/v1/user/loan-applications/{id}
9

Loan Disbursement

Admin/staff disburse approved loan. The net loan amount funds the customer's wallet first, while the LOAN_REPAY account balance increases by the loan principal to track outstanding loan balance. Referrer receives commission notification.

GET
/api/v1/user/loans
View disbursed loans
GET
/api/v1/user/loans/{id}
Get loan details with repayment schedule
GET
/api/v1/user/loans/{id}/schedule
View loan repayment schedule
ℹ️ Ledger entries generated. Funds hit the customer's wallet first; LOAN_REPAY tracks the loan transaction audit trail. Referrer receives commission via push notification.
9.5

Loan Repayment

Customer makes loan repayments using wallet balance, either partial payments or full payoff

GET
/api/v1/user/loans/{id}/schedules
View loan repayment schedule with due dates and amounts
GET
/api/v1/user/loans/{id}/repayments
View repayment history for this loan
POST
/api/v1/user/loans/{id}/repayments
Make partial or full loan repayment from wallet
GET
/api/v1/user/loans/{id}/payoff-quote
Get payoff quote with penalties and total amount due
POST
/api/v1/user/loans/{id}/payoff
Process full loan payoff from wallet
⚠️ Repayments require sufficient balance in customer's wallet account. System validates balance before processing.
ℹ️ Payoff quotes include any applicable early repayment penalties. Quotes are valid for 24 hours.
Sample Repayment Payload: 
{
  "source_account_id": "uuid-of-wallet-account",
  "amount": 50000.00,
  "payment_type": "partial",
  "reference": "Monthly repayment"
}
Sample Payoff Payload: 
{
  "source_account_id": "uuid-of-wallet-account",
  "reference": "Full loan payoff"
}
